# Norm 路线图

这一版（Demo，`norm.ntnl.io`）已经把五条硬承诺里**能用一个 Worker 兑现的部分**全部落到了线上。
下面按「哪一条承诺还没兑现」组织，不按工时组织。

## 已完成（Demo）

- Ed25519（base58）身份：公钥即地址，逐请求签名，nonce 防重放，无会话无密码
- BYOK：客户端 XChaCha20-Poly1305 密封，服务端只存密文；明文密钥只走一次请求头
- 逐请求隔离计费：`requests` + 纯追加 `ledger`，整数纳美元，失败收 Gas、token 按量
- 上游提供商来源核验：`host` / `key_prefix` / `models_probe` 三路信号，公开可读
- ZDR：不留请求体、响应体、上游提供商密钥；`/api/v1/attestation` 公开构建哈希
- 可信发布：GitHub Actions 构建 → 算哈希 → 部署 → 上线后自校验哈希一致

## 待做：计费链上化（第 3 条承诺）

- 现在：演示授信用完即止，没有充值入口。
- 目标：用 EVM 链上 USDC/USDT 充值，走 Midas 的纳美元账本（带 pre/post 余额链）。
- 关键设计问题：**Worker 不能持有私钥**。收款地址只用来收款，入账靠链上事件扫描 +
  用户自签的「这笔钱属于地址 X」凭据，而不是靠服务端猜测。
- 在那之前，这个 Demo 不接真实支付，也不做「余额不足就自动降级」的花哨逻辑。

## 待做：来源核验从「信号」升级为「证据」

- 现在：`host` 与 `key_prefix` 是启发式信号，`models_probe` 是可用性探测。
- 目标：让上游提供商自己在响应里签名（例如 `-LB` 一族已具备的审计日志），Norm 只做验签与展示；
  同时把每次核验的原始响应摘要留档，供第三方重放。
- 一个必须承认的边界：**官方订阅额度无法在协议层证明**，只能标注「声明」并公开核验信号。

## 待做：可信发布的完整闭环

- 现在：证明「线上跑的字节 == 这个 commit 构建出来的字节」（`source_sha256` / `assets_sha256`）。
- 目标：把 Worker 产物也钉进 Release（附 SHA256），并让 attestation 页直接链到那次 Release，
  这样连「构建用了什么依赖」也能自证（`pnpm-lock.yaml` 已经在仓库里）。

## 明确不做

- 不做跨方言的工具调用（同格式直通时 `tools` 原样穿过，跨方言带 `tools` 直接 400）
- 不做模型路由与限速策略（这一版的定位是「一份可复现的转发规则」）
- 不做运营后台：没有管理员、没有用户列表、没有封禁
